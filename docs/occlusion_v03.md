# v0.3 遮挡视觉升级（本地待审）

## 实现

本阶段仅改屏幕识别、观察字段、可见内存清理与调试输出。实时输入仍是 Windows 截图；`FullState`、APK 内部隐藏牌、网络和 ADB 不进入识别或点击链。`BasicPlanner` 与点击事务保持原有策略和阈值。

1. **亮牌检测**继续用原始 `block_1`–`block_16` 模板和既有阈值。全局匹配先给出较完整的可见牌，暗牌若能完整匹配也保留其类型。
2. **明暗分开判断**：使用原背景模板与黑罩 Alpha 合成后的背景模板比较边缘误差；稳定暗化的牌标为 `shade_state=dark`，不提升为可点击。即使暗牌的整个图案可见，也可保留 `visibility=full`，表示画面完整度而非合法点击。黑罩像素来自本地 APK 提取素材，纹理内部 Alpha 102。模板相关系数只称为 `sim`，不是正确概率。
3. **局部遮挡搜索**：以已识别亮牌为锚，按半牌宽的行列偏移产生少量候选位置。这里的偏移是搜索提议，不宣称关卡只使用这种模式。多个已观察亮牌的矩形求联合遮挡掩码；仅在仍露出的图案像素上与动态合成的暗模板比较。要求至少 15% 图案像素且不少于 100 个像素、相似度至少 0.92、RGB 平均误差不超过 22、最佳类别比分数第二名高至少 0.05。低于这些条件时不强行分类；完全不可见的牌不创建对象。
4. **观察边界**：`ObservedTile` 增加 `shade_state`、`occlusion_fraction` 与 `occlusion_source`。`observed_overlap` 只表示屏幕几何推断，不是 APK 内部层级事实。暗牌、遮挡牌仍不可点击。局部记忆在连续两次覆盖其完整范围的局部观察中未见某个旧部分牌时清除它，避免假阳性长期残留。
5. **调试**：绿色可点、蓝色暗牌、琥珀色部分可见、灰色不确定；图上标出类型、匹配分数、明暗、可见状态、局部坐标和不确定原因。手动 GUI 识别时将结构化 JSON 与调试 PNG 一起写到本地 `data/screenshots/`；自动循环不新增逐步截图保存。

`vision/occlusion.py` 只实现矩形联合掩码、黑色 Alpha 合成和有掩码的相似度。按实际素材尺寸缓存缩放模板、黑罩和暗色图案，缓存上限分别为 128、32、128 项。图案分类与可点击判断分开；此前可点击候选未因新算法扩大。

## 验证与性能

2026-10-28，本机 Python/Windows。原版素材和截图只用于**本地**额外回放，均不提交公开仓库。优化前先运行 `pytest`：43 项通过；`scripts/benchmark_synthetic.py` 基线完整识别 P50/P95 136.74/141.86 ms，局部 51.62/55.43 ms。测试负载是三种程序生成的图案，没有黑罩，与真实画面耗时不可直接混比。

| 同一私有截图、16 个本地经典模板、同一进程各 5 次回放 | v0.2 P50/P95 | v0.3 P50/P95 |
|---|---:|---:|
| 完整识别 | 1674.0 / 1695.8 ms | 1786.1 / 1791.4 ms |
| 局部识别 | 209.8 / 212.0 ms | 215.8 / 217.7 ms |
| 主牌候选 | 20 | 31（其中 11 个暗牌） |
| 原有可点击候选 | 16 | 16（同一组坐标和类型） |

以上截图候选数**不是**准确率；两版性能在同一机器和固定校准下测量，P95 样本仅 5 次，波动较大。新算法增加计算量，换取部分暗牌识别；首次实现的完整识别约 2.6 秒，加入暗模板缓存后在重复测量中约 1.75–1.79 秒。局部增量识别仍只处理受点击影响的小区域。

公开合成评估运行 `scripts/benchmark_occlusion.py`：7 个场景、11 张有标签的可见牌、16 个程序生成的固定图案；检测精确率/召回率均 11/11，匹配牌型 11/11、明暗 11/11，假可点 0。相同场景旧版只检出 7/11，精确率 7/7；旧版没有明暗字段。最终版本合成完整识别 P50/P95 246.68/714.57 ms，局部 89.44/275.36 ms；不同缩放场景混在一起，P95 受 2 倍缩放影响。普通三图案合成基准最终完整识别为 130.06/136.69 ms、局部 35.00/36.86 ms、40 次模拟周期 RSS 为 50.93→51.84 MiB；与优化前同基准的 136.74/141.86 ms、51.62/55.43 ms 相比没有持续性内存增长，但波动和样本配置限制了加速结论。合成随机图案易于区分，**不代表真实截图准确率**。

真实截图的非完整人工核对：32 个选定可见牌中定位到 29 个，漏 3 个；已定位的 29 个牌型与明暗标记一致，已标暗牌被误判可点击为 0。标注在算法输出之后制作、只覆盖人工能够看清的部分，因此不能计算真实全图精确率、召回率、真实可点击准确率，也不能当独立保留测试集。未来应跨日期、版本和皮肤重新人工标注完整画面，尤其记录游戏实际接收点击的结果。

## 复现命令

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
.venv\Scripts\python -m pytest -q
$env:PYTHONPATH='src'
.venv\Scripts\python scripts\benchmark_synthetic.py
.venv\Scripts\python scripts\benchmark_occlusion.py
.venv\Scripts\python scripts\evaluate_manual_screenshot.py data\research\occlusion_spotcheck.json
```

最后一条需要本机私有截图、模板和标注；公开克隆只可运行前面的合成测试。原版素材和私有标注位于 `.gitignore` 排除的目录。

## 剩余风险

- 新搜索只尝试已见亮牌附近的半牌宽位移；其他错位、极小可见面积、全遮挡牌仍可能漏检。极少像素时保留不确定而不是猜类型。
- 单帧几何不能证明真正层级；深层重叠和多个暗牌互挡未恢复完整遮挡图。
- 黑罩纹理 Alpha 与补间目标已有静态证据，但 prefab tint、混合模式及实际屏幕色彩未逐像素验证。动画期不得识别；原控制器稳定画面验证仍是必要条件。
- 真实点击合法性和新暗牌识别在 Windows 游戏窗口中的同步实验尚未执行。本阶段没有扩大自动点击范围，也没有更改安全阈值。
